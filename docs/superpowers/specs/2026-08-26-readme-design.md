## 專案定位

問題描述聚焦於短劇創作的可製作性與一致性：一般生成結果容易出現結構鬆散、角色動機跳躍、臺詞只解說背景、場次格式不一致、反轉缺乏線索，以及使用者只要求劇本時仍越界產生分鏡或影片提示詞。

本技能透過明確任務路由、八階段編劇流程、標準格式與審閱清單，將故事前提轉化為可見、可聽、可拍攝且具戲劇推進的短劇內容。

## 主要功能

功能描述必須能追溯至 `skill-src/ai-short-drama-screenwriter/`：

- 完整流程：創作簡報、題材定位、全劇與單集結構、角色關係、分場、臺詞、衝突／情緒／反轉／鉤子、初稿與修改。
- 單點創作：只交付使用者指定的選題、結構、角色、分場、臺詞、衝突、反轉或格式成果。
- 標準格式：場次、內景／外景、地點、時間、動作、角色名稱、臺詞與畫面文字。
- 審閱修改：依影響程度提供問題、證據、影響與可執行修正方向。
- 限制保持：保留指定集數、時長、觀眾、類型、平台、預算、場景及交付形式。
- 繁體中文：預設以繁體中文輸出，但不把語言寫成觸發限制。
- 跨技能銜接：混合需求先完成劇本，再銜接已安裝且適用的分鏡或影片技能。

## 安裝設計

依 [OpenAI 官方技能文件](https://learn.chatgpt.com/docs/build-skills)，個人技能放在 `$HOME/.agents/skills`；技能資料夾的直接子檔案必須包含 `SKILL.md`。README 提供下列步驟：

1. 確認已安裝 Git 及支援 standalone skills 的 Codex。
2. Clone `https://github.com/POUND0423/AI-drama-pound.git`。
3. 建立個人技能目錄。
4. 複製 `skill-src/ai-short-drama-screenwriter` 的內容。
5. 驗證目標資料夾內直接存在 `SKILL.md`。
6. 若技能未出現，重新啟動 Codex。

### Windows PowerShell

命令使用 `[Environment]::GetFolderPath('UserProfile')` 建立使用者根路徑，避免假定工作目錄。目標為：

`%USERPROFILE%\.agents\skills\ai-short-drama-screenwriter`

### macOS／Linux

命令使用 `$HOME/.agents/skills/ai-short-drama-screenwriter`，並以 `mkdir -p` 與 `cp -R <source>/. <target>/` 保留技能目錄結構。

命令不得刪除其他技能，也不得要求系統管理員權限。

## 使用設計

README 同時說明兩種啟動方式：

- 顯式：在提示中輸入 `$ai-short-drama-screenwriter`。
- 隱式：直接提出符合技能 description 的短篇或豎屏短劇創作、格式化、審閱或修改需求。

顯式範例：

```text
使用 $ai-short-drama-screenwriter，把以下故事前提規劃成 8 集、每集 90 秒的都市懸疑短劇。主要場景不超過 3 個；先提供創作簡報、角色關係、全劇節拍與第一集劇本。

故事前提：外送員每天替一位失憶老人送餐，最後發現老人可能是失蹤多年的外公。
```

## 輸入輸出範例設計

輸出展示精簡節錄，不假裝是固定模板或保證逐字結果。節錄依序包含：

1. 必要假設。
2. 創作簡報。
3. 角色關係。
4. 八集節拍的代表性項目。
5. 第一集標準劇本片段。

劇本片段必須使用真實格式，例如：

```text
第 1 集

1. 內景・老公寓走廊・夜

阿澤提著餐袋停在 302 室門前。門縫下壓著一張泛黃照片。

阿澤
陳伯，您的晚餐到了。
```

範例必須保留 8 集、90 秒與 3 個主要場景限制，並以集尾問題或代價收束；不得加入鏡號、景別、運鏡或影片模型參數。

## 功能邊界與常見問題

- 本倉庫不包含分鏡或 AI 影片提示詞技能；混合交付只有在環境中另有適用技能時才能繼續銜接。
- 使用者只要求劇本時，輸出不包含逐鏡分鏡、景別、運鏡或影片提示詞。
- 平台偏好、演算法與市場趨勢不是內建靜態知識；涉及當前資訊時必須先查證。
- 找不到技能時，先檢查 `SKILL.md` 是否位於正確資料夾的直接子層，再重新啟動 Codex。
- README 不承諾每次輸出內容相同；輸出會依故事前提、限制與指定交付形式改變。
