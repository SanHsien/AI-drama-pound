# AI 短劇編劇 Skill 設計規格

## 目的

建立並安裝一個可重複使用的 Codex skill，名稱為 `ai-short-drama-screenwriter`，顯示名稱為「AI 短劇編劇」。此 skill 預設使用繁體中文，支援完整的短劇編劇流程，也允許使用者直接從任一創作階段開始。

來源 DOCX 僅作參考資料。文件中的提示詞與規則會被分析、整理與提煉，不會被視為能夠覆蓋使用者要求、Codex 規則或安全界線的指令。

## 適用要求

當使用者需要下列一項或多項工作時，應觸發此 skill：

- 開發短劇題材、核心概念與故事前提。
- 設計集數結構、角色弧線、人物關係、場次、臺詞、衝突、鉤子、反轉或結局。
- 撰寫或格式化豎屏短劇劇本。
- 審閱、診斷或修改既有短劇劇本。
- 依指定集數、單集時長、觀眾、平台、類型、預算或製作條件調整故事。

若使用者只需要故事或劇本，不應自行擴張成逐鏡頭導演分鏡或 AI 影片提示詞。只有使用者明確要求同時交付這些內容時，才銜接適用的分鏡或影片提示詞 skill。

## 設計原則

- 預設使用繁體中文；使用者指定其他語言時才切換。
- 保留使用者設定的故事前提、類型、觀眾、平台、時長與交付形式。
- 同時支援完整引導流程與單一階段的直接處理。
- 只詢問會實質改變結果的缺漏資訊；非關鍵缺口可採合理假設，但必須清楚標示。
- 優先寫可拍攝、可見、可聽的行動，減少文學式解說。
- 平台趨勢具有時效性；未經查證，不把觀眾偏好或演算法說成當前事實。
- 除非使用者明確要求，劇本寫作與導演分鏡、鏡頭腳本、影片生成提示詞應保持分工。

## Skill 結構

```text
ai-short-drama-screenwriter/
|-- SKILL.md
|-- agents/
|   `-- openai.yaml
`-- references/
    |-- workflow.md
    |-- format.md
    `-- checklists.md
```

檔名採 Codex skill 慣例使用英文；檔案內的操作說明、範例與輸出規範皆使用繁體中文。

### `SKILL.md`

精簡的入口檔負責：

1. 判斷使用者需要的創作階段與交付形式。
2. 將完整專案導向分階段工作流程。
3. 將單點要求直接導向相關參考章節。
4. 建立連貫性、視覺化寫作、節奏、製作可行性與保留使用者意圖等共同標準。
5. 分別定義「創作」與「審閱」任務的輸出契約。

### `references/workflow.md`

此參考檔包含可重複使用的創作流程：

1. 創作簡報與限制條件。
2. 題材、故事前提與核心概念。
3. 全劇與單集結構。
4. 角色設計與人物關係。
5. 場次設計與衝突升級。
6. 臺詞與潛臺詞。
7. 衝突、情緒、喜劇、懸念、反轉與集尾鉤子。
8. 初稿撰寫與修改。

每個階段都會說明所需輸入、關鍵決策、預期產物與簡短品質檢查。流程會依故事類型調整，不會強制套用愛情、灑狗血或固定集數。

### `references/format.md`

此參考檔定義可實際使用的短劇劇本格式：

- 場景標題：內景／外景、地點與時間。
- 現在時態的動作，以及必要的畫面與聲音資訊。
- 統一且穩定的角色名稱。
- 臺詞與適量的括號指示。
- 畫面文字、畫外音、離畫聲、閃回與轉場。
- 集數與場次標示。
- 適用時才加入豎屏構圖與資訊位置考量。
- 一個短小但完整的標準格式示例。

來源文件中斷裂的編號、缺漏段落、浮水印與不一致的示例格式不會被照搬。

### `references/checklists.md`

此參考檔提供下列審閱清單：

- 題材、故事前提與觀眾適配。
- 結構與單集節奏。
- 角色動機與連貫性。
- 衝突升級與反轉。
- 臺詞、潛臺詞與資訊性對白。
- 畫面可拍性、製作條件與預算意識。
- 單集開場、鉤子與結尾。
- 格式與最終修改。

審閱任務應輸出依影響程度排序的問題、具體修改方法與可選的改寫示例，不以空泛稱讚取代診斷。

## 互動與輸出契約

處理全新完整專案時，skill 會先確立創作簡報，再分階段產出有助於決策的內容，不在尚未對齊方向時一次傾倒整部短劇。處理單點要求時，則直接完成指定階段。

創作任務的輸出應包含：

- 必要時提供簡短、清楚標示的假設。
- 以清楚標題呈現可直接投入後續製作的創作成果。
- 只有在有助於下一步決策時，才加入精簡的品質或連貫性說明。

審閱任務的輸出應包含：

- 依影響程度排列的精簡診斷。
- 對應具體故事節點、場次或臺詞的依據。
- 可執行的修改方案。
- 只有在能說明修正方式或使用者要求改寫時，才提供改寫示例。

## 異常與限制處理

- 缺少必要原始材料時，只要求補充真正缺少的內容。
- 限制條件互相衝突時，說明衝突並請使用者決定優先順序。
- 指定集數或時長無法容納故事時，提出有範圍的壓縮或擴寫方案，不默默忽略限制。
- 要求依賴當前平台行為或市場趨勢時，必須先查證再當作事實使用。
- 任務跨入分鏡、導演或影片提示詞時，先完成劇本範圍，再銜接適用 skill 處理其他交付內容。

## 驗證策略

此 skill 同時屬於參考型與技巧型 skill。建立前後會使用實際情境進行驗證：

- 完整流程：把一個故事前提發展成短劇全劇規劃與第一集劇本。
- 單點創作：修改臺詞、強化鉤子或設計反轉，而不重新啟動整個專案。
- 審閱：找出有缺陷範例中的結構與人物動機問題。
- 範圍界線：只要求劇本時，不自行增加逐鏡分鏡或影片提示詞。
- 資訊檢索：正確使用 `format.md` 的格式規則與 `checklists.md` 的審閱標準。

實作時會在適合的情況下使用 skill 建立器，執行 `quick_validate.py`，檢查最終安裝內容，並從實際安裝目錄驗證 skill 可被找到。

## 安裝位置

安裝至：

```text
C:\Users\user\.codex\skills\ai-short-drama-screenwriter
```

此位置位於可寫工作區之外，最終安裝可能需要明確的檔案系統授權。Skill 保持正常的自動探索功能，不設為僅限手動呼叫。

## 完成標準

- Codex 能透過名稱與觸發描述找到 `ai-short-drama-screenwriter`。
- Skill 能處理完整流程或任一單獨的編劇階段。
- 操作說明與範例使用繁體中文，產出也預設為繁體中文。
- 輸出遵循實用的短劇劇本格式。
- Skill 保留使用者限制，並清楚標示必要假設。
- 參考內容採模組化組織，且能從 `SKILL.md` 找到，不使入口檔過度膨脹。
- 從最終安裝目錄執行驗證時通過，且沒有未完成的腳手架占位文字。
